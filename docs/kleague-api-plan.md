# K리그 공식 API로 선수 데이터 만들기 (계획 메모)

> 친구/ChatGPT가 정리해 준 설계를 이 프로젝트 기준으로 줄여서 적어둔 메모예요.
> **아직 API 키를 받기 전이라, 아래 엔드포인트와 파라미터는 실제 문서로 확인된 것과 아닌 것을 구분해 뒀어요.**

## 확인된 것 (공식 문서를 직접 본 것)

| API | 내용 | 확인 |
|---|---|---|
| `GET /api/HAPlayerRecord.do` | 선수 시즌 기술통계(출전, 도움, PK, 슈팅, 유효슈팅, 파울, 경고, 퇴장 등), 전체/홈/어웨이 | 문서 확인 |

- 호출 주소: `https://api.kleague.com/api/HAPlayerRecord.do?meet_year=2026&meet_seq=1&home_type=0&excludingPO=N`
- 인증: 헤더 `authKey: 키` 권장 (2027년부터 Bearer 토큰으로 통합 예정)
- 응답: `response.resultCode`가 `"00"`이면 성공, 선수 목록은 `response.list`
- **이 응답에는 골 수, 출전 시간, 포지션이 없어요.** (예시 JSON 기준)
- 팀 이름은 약칭(예: "인천"), 팀 코드 `TEAM_ID`, 선수 코드 `PLAYER_ID` 제공

## 확인 필요한 것 (설계안에서 언급됐지만 문서는 아직 못 봤어요)

| API | 용도 | 확인할 것 |
|---|---|---|
| `playerRank.do` | 시즌 선수 종합기록(득점 등) | 파라미터 `seasonYN`(이적 선수 기록 합산 여부)가 맞는지 |
| `meetSchedule.do` | 경기 일정, `GAME_ID`, 홈/원정, 라운드 | 응답 필드 이름 |
| `matchPlayerRecord.do` | 경기별 선수 기록(슈팅·패스·챌린지·공중볼 등) | 파라미터 `team_id`, `game_id` |
| 선수 기본 정보 | 포지션, 출생 | 어떤 API인지 |
| 패스 매트릭스, 타임시트 | 선수 간 패스, 행동·좌표 | 실제 제공 여부, 이용 범위 |
| `meet_seq` 값 | K리그1/K리그2/컵 구분 | 값의 의미 |

→ 키를 받은 뒤 각 API 문서 화면을 복사해서 이 표를 채워 주세요.

## 만들 순서

1. **수집**: `tools/fetch_kleague.mjs`로 원본 JSON을 `data-raw/`에 저장 (이미 있음, HAPlayerRecord만 지원). 원본은 버리지 않고 보관해요. 계산식을 바꿔도 API를 다시 부를 필요가 없게요.
2. **합치기**: 선수 코드(`PLAYER_ID`)를 기준으로 시즌 기록 + 기록순위(골) + 기본 정보(포지션)를 한 표로.
3. **능력치 변환**: 아래 원칙으로 1~99 능력치 생성.
4. **내보내기**: 게임이 읽는 `data.js` 형식으로 변환 (시즌별 선수 + 세부 포지션 + 능력치).
5. 이후: 폼(최근 5경기) 반영, 이벤트 기반 경기 시뮬레이션.

## 능력치 변환 원칙

- **절대값이 아니라 상대 위치(퍼센타일)로 변환**한다. "골 18개 = 높음"이 아니라 "같은 포지션 선수들 중 상위 몇 %"로. 포지션끼리 섞어서 비교하지 않는다.
- **포지션별 가중치를 다르게** 쓴다. (예: FW는 득점·슈팅·유효슈팅·공격포인트, MF는 도움·패스·활동, DF는 수비 지표·카드)
- **실측으로 계산한 능력치와 추정한 능력치를 구분해서 저장**한다. 예: `rating_source: "official_stat" | "estimated"`. API에 없는 항목(예: 스피드)을 실제 기록인 것처럼 만들지 않는다.
- 출전 시간이 적은 선수는 표본이 작으므로 능력치를 평균 쪽으로 당긴다(보정).
- 시즌 능력치와 별도로 **프라임(최고 시즌)**, **폼(최근 5경기 비중 60% + 시즌 40%)**을 계산할 수 있다.

## 지금 게임과 연결하는 방법

- 지금 게임은 선수당 `ovr`(종합 능력치) 하나와 세부 포지션을 써요. 처음에는 API 기록으로 `ovr`만 정하고, 시즌별 값은 `data.js`의 선수 항목(시즌)에 그대로 넣으면 돼요.
- 능력치를 여러 항목(패스, 드리블 등)으로 세분화하는 건 경기 엔진을 바꿔야 해서, 종합 능력치 변환이 먼저 된 뒤에 해요.
- 현재의 나이 곡선 기반 시즌 능력치(`js/born.js`, `CONFIG.AGE_*`)는 실제 기록으로 대체되면 필요 없어져요.

## 주의

- **이용약관 확인**: API로 받은 원본 데이터를 공개 저장소·사이트에 그대로 올려도 되는지 확인하세요. 그래서 `data-raw/`는 `.gitignore`에 넣어 두었어요. 게임에는 계산한 능력치만 쓰는 쪽이 안전해요.
- **API 키는 브라우저 코드에 넣지 않아요.** 내 컴퓨터에서 한 번 받아 파일로 저장하는 방식으로만 써요. (`.env`는 git에 올라가지 않아요)
- 받을 수 있는 과거 연도 범위는 호출해 봐야 알 수 있어요.
